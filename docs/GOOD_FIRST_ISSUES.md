# Good first issues

These are bounded contribution shapes, not claims that public issues already exist. A maintainer should turn one into an
issue after confirming it is still useful.

1. Add a recorded malformed metadata fixture for an existing npm, PyPI, or Cargo adapter.
2. Add a deterministic regression test for an existing diagnostic category.
3. Improve one CLI error message while preserving documented exit codes.
4. Add a documentation example that uses an existing fixture and verify it locally.
5. Add a fixture-matrix entry for an already-supported failure mode.

Every contribution should follow `docs/CONTRIBUTOR_GUIDE.md` and `docs/ADAPTER_GUIDE.md` where applicable. Do not begin a
new ecosystem or funding provider as a good-first issue without maintainer approval.
